# The test suite run of 2026-11-09

The first full run since the 2026-11-05 review. Every card at its defaults on the frozen
inputs in the assets folder, then the comparisons (stage 6) and options (stage 7):
105 runs, from 07:38 to 11:36 UTC, on the master (RTX 5090, 32 GB). This was question 19 of
[the review](../review-2026-11-05.md). Your comments go in
[showcase-feedback-2026-11-09.md](../showcase-feedback-2026-11-09.md).

## Results

- **104 of 105 clean, none failed by itself.** The one failure is
  `video_edit_bernini_r_video_editing@fast-off`, which I interrupted (below).
- **Every picture and the middle frame of every video was opened** (contact sheets of all
  99 visual outputs): none black, flat or broken, each what its card is for. Motion and
  sound were not judged: that is the owner's pass.
- **One automatic flag:** `audio_stable_audio_3_medium`, clipping. To listen to.
- **The cards that used to get a black placeholder picture** (fixed 2026-11-05) no longer
  fade in from black: the first frames of FastH3 i2v (and its 2:3 comparison), FastH3
  OmniRef, Pika ref2va and the MiniMax seamless loop are as bright as their middle frames.
- **Timings:** 51 cards changed; four by more than a quarter. VRAM peaks only go up
  (TripoSplat 3.6 → 4.1 GB, Wan IdV2V hires 14.9 → 18.2 GB). FLUX.2 Klein 9B t2i went from
  16 to 12 s. **Krea 2 style reference went from 32 to 15 s warm on the same input and
  steps (0.23 → 0.50 steps/s), and nothing in the run explains it.** The earlier run was
  probably slowed by something else; re-time it if the number matters.

## Exact replay (question 23)

Four cards were run again from the settings their examples record: MOSS t2i, Ideogram 4,
LTX 2.5 i2v and Stable Audio 3. **All four give identical pixels and samples.** The MP3's
bytes differ, but only in its metadata.

The first attempt found a real bug. The sweep cut every recorded value at 2000 characters,
and seeding completed a cut value from the card's graph literal, which is its default
prompt. Four suite prompts are longer than 2000 characters. For three of them, Ideogram,
Pika ref2va and FastVideo omniref, the example would have recorded another prompt, and
"Use these settings" would have made another picture. Fixed in `4d5b43a`: values are
recorded whole, and seeding refuses to complete a value it cannot know. The published
report was repaired from the suite file.

Rerunning a card from the suite is not the same check: a suite that does not set a seed
gets a fresh one each run, recorded. The replay has to use the recorded seed.

## The interrupted run

`video_edit_bernini_r_video_editing@fast-off` (832×832, 5 s, 20 steps, guidance on) filled
the 32 GB card and spilled into system memory: 385 s per step, then 917. Fast mode on, at
3 steps, peaks at 21.8 GB and runs a step in about 58 s. It would have run into the
sweep's 2-hour limit, so it was interrupted by hand at step 2.

**Fast mode off is not usable at the card's default size on this machine.** For the
comparison, run it smaller (640×640, or 3 s) or drop the variant.

The interrupt showed a second bug. ComfyUI ends an interrupted prompt with the same
message as a finished one, so the sweep recorded the run as ok with one output (a stray
text). Fixed in `40fb36f`: a job stopped in ComfyUI now fails with "Stopped in ComfyUI
before it finished". The report row was corrected by hand.
