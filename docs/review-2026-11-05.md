### Question 31: when should the launcher re-run `npm install`?

"The lockfile is newer than `node_modules`" never fires after a pull. The root, client and server `package-lock.json` files are gitignored (`.gitignore:8`; only `desktop/package-lock.json` is tracked), so `git pull` never changes them. The rule would also fire wrongly on this rig today: npm rewrote the lockfiles on 2026-11-05, while `node_modules` dates from June and July.
- a) After each successful install, save a hash of the dependency lists in the three `package.json` files (for example `node_modules/.comfyq-deps`). Re-install when the hash changes.
- b) At launch, run `npm ls --depth=0` for the root, client and server, and install when it fails. This adds a few seconds to every start.
- c) Commit the three lockfiles, so every rig installs the same versions. Combine c with a or b.
- **Recommend a + c.** If the install fails (for example on an offline rig), start anyway with a warning, as agreed. About 1 hour.
