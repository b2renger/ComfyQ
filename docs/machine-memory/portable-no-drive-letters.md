The ComfyQ ComfyUI install is **portable on an external NVMe** that the owner plugs into different machines (RTX 3090/4080/4090/5090/A6000/A6000 Pro — but Ampere (3090/A6000) cannot run the 3D packs' sm_89 CUDA wheels, see [[pixal-trellis-portable-install]]; `tools/maintenance/README.md` lists Ampere as unsupported for the whole drive), where it mounts under **different drive letters** (seen as `J:` on the current rig). Nothing on that drive may bake in an absolute path or drive letter — it must all be relative to the install so it stays fully portable.

**Why:** an absolute `J:\...` path silently breaks the moment the drive mounts as `K:`/`D:`/etc. on another machine. The owner explicitly called this out after I (wrongly) patched example-workflow paths to absolute `J:\...\output\...` — they want **paths relative to the comfy install folder**.

**How to apply:**
- **ComfyUI node paths** (Load3D/Preview3D/`Trellis2LoadMesh` `glb_path`, etc.): use the ComfyUI-native **relative** form — a bare filename or `subfolder/name.glb`. ComfyUI resolves these against the install via `folder_paths.get_input_directory()` / `get_output_directory()` (derived from where `main.py` lives, drive-independent). `Trellis2LoadMesh` specifically: if `os.path.exists(glb_path)` is False it falls back to `<ComfyUI>/input/` + `glb_path`.
- **The pack authors bake their own machine's absolute paths** (e.g. `C:\Git\ComfyUI\output\...`) into example workflows → they trigger a `view_image` "Paths don't have the same drive" crash (unguarded `os.path.commonpath` across drives) and `Trellis2LoadMesh` "string is not a file". Fix by stripping to the driveless output/input-relative tail. These revert on a pack update — re-run the fix (**`ComfyQ/tools/maintenance/portablize_paths.py`** — see below).
- **.bat launchers** (`run_nvidia_gpu*.bat`, `run_cpu.bat`): they use the relative `.\python_embeded\python.exe` path, so they are already drive-independent, and they set **no cache env vars** — only flags (`--windows-standalone-build --listen 0.0.0.0`, plus `--fast fp16_accumulation` on one). Checked 2026-11-05.
- **ComfyQ server** ([comfyProcess.js](server/workers/comfyProcess.js)) sets no cache dirs either — only `PYTHONIOENCODING` and `PYTHONUNBUFFERED`. So the HuggingFace, triton and inductor caches fall back to the system drive.
- ⚠ **Do NOT add cache env vars (`HF_HOME`, `TRITON_CACHE_DIR`, `TORCHINDUCTOR_CACHE_DIR`) to the launchers or to comfyProcess.js.** I did once; the owner flagged it and both were reverted (see [[pixal-trellis-portable-install]], scope note). An earlier version of this memory told you to do exactly that — it was wrong.
- The **system-drive leak is therefore a known, unsolved limitation**, not something already handled: the HuggingFace cache defaults to `%USERPROFILE%\.cache`, and pixi/`comfy-env` envs land at `C:\ce`/`%LOCALAPPDATA%`. Keep new changes from adding to it. See [[pixal-trellis-portable-install]].

**comfy-env / pixi packs (the big C: portability leak):** some packs (PozzettiAndrea's **ComfyUI-DepthAnythingV3**, **ComfyUI-GeometryPack**) use the `comfy-env` package to run in **isolated pixi envs on C:** (`%LOCALAPPDATA%\Programs\comfy-env\.pixi\envs\*` + `pixi.exe` at `%USERPROFILE%\.pixi`) — inherently non-portable (pixi hardcoded to C:, envs embed absolute paths). Fix per-pack:
- **If the pack's deps are already in the embedded Python** (DepthAnythingV3's all were — flash_attn/sageattention/transformers/etc.), **de-isolate it**: add `[settings]\nisolate = false\ninstall_isolated = false` to the pack's `comfy-env-root.toml` (per-node settings override env vars, `resolve_bool` in `comfy_env/settings.py`), and rename `nodes/comfy-env.toml` → `.disabled` so no isolation env is declared. Then it runs in-process on the NVMe. **Verified 2026-07-07**: DepthAnything_V3 registers + produces depth maps in-process with zero C: footprint. `comfy_env` the *package* stays installed (used for `register_nodes`).
- **If the pack needs conda-only libs** (GeometryPack needs `cgal`/`igl`/`bpy`(Blender)/`pyvista`) it **can't** go in the pip embedded Python → not portable. If unused (GeometryPack is used by no ComfyQ workflow), disable it: move it out of `custom_nodes/` (to `_disabled_custom_nodes/`).
- Then delete the stale C: pixi envs + `%LOCALAPPDATA%\Programs\comfy-env` + `%USERPROFILE%\.pixi`; they don't reappear once nothing isolates.

**`/view` cross-drive crash (portable-drive-specific ComfyUI core bug):** ComfyUI's `/view` route (`server.py` `view_image`) calls `os.path.commonpath` unguarded; on Windows that raises `ValueError: Paths don't have the same drive` when a requested path is on a different drive than the output dir → 500 + traceback. Hits portable installs because `Preview3D`/`Load3D` (and 3D packs) store **absolute** paths — when the drive later mounts under a different letter, the stored path is cross-drive. **Don't patch `server.py`** (a ComfyUI update reverts it). **Durable fix = the `ComfyUI-CrossDriveViewFix` custom node** (built 2026-07-07; owner will publish to `github.com/b2renger/ComfyUI-CrossDriveViewFix`): a node-less pack whose `prestartup_script.py` wraps `os.path.commonpath` to return `""` on the different-drive `ValueError` (→ clean 403) and re-raise all others. Lives in `custom_nodes/` (survives core updates, travels with the drive), no-op elsewhere. Verified: cross-drive `/view` → 403 not 500. **★ Pattern:** to durably fix a ComfyUI *core* bug, use a custom-node `prestartup_script.py` monkeypatch, never edit core files. (`mmgp not installed` from TRELLIS2 is a harmless info line — the code handles its absence, Desktop-only; no action.)

**ComfyUI-Manager "Your ComfyUI isn't git repo" (verified 2026-07-07):** a **false alarm from git's "dubious ownership" guard**, not a broken repo. The `ComfyUI` folder IS a valid git checkout (`.git` HEAD→`refs/heads/master`, remote `comfyanonymous/ComfyUI`), but the NTFS folder carries the **owner SID of the machine/user that first set up the drive**; on any other rig the logged-in user's SID differs, so git errors `fatal: detected dubious ownership in repository at '...'` and refuses every operation — Manager runs a `git` detect, it fails, Manager mis-reports "isn't git repo." **Recurs on EVERY machine** (each has a different user SID than the folder's stored owner), and also silently affects every `custom_nodes/*` repo (same foreign SID). Harmless to running ComfyUI — only blocks Manager's git version-track / "Update ComfyUI". **Fix (per-machine, one-time):** `git config --global --add safe.directory "*"` — wildcard is right here because the drive **remounts under different letters** (a path-specific `safe.directory J:/...` breaks when it's `K:`, and wouldn't cover custom_nodes). **★ Not bakeable into the drive:** git deliberately reads `safe.directory` only from **global/system** gitconfig, never the repo's own config (so a repo can't self-trust) — so it must be set once per machine/user; there's no drive-resident cure. Re-enables Manager's core "Update ComfyUI" (a git pull; safe re: torch — bare `torch` in requirements.txt won't upgrade an already-satisfied 2.8.0), but **still never run `update_comfyui_and_python_dependencies.bat`** (see [[pixal-trellis-portable-install]] + the drive's `notice.md`).

**Re-apply hub — now `ComfyQ/tools/maintenance`, in the REPO (moved 2026-10-06; the old `<nvme>\ComfyUI_windows_portable_nvidia\_maintenance\` folder is DELETED).** A fix typed into a pack or the install by hand exists on exactly one machine, reverts on a pack update, and is absent from every rig imaged from the drive — so the patch text lives in the repo and the install is brought up to it. Scripts resolve the install through `tools/maintenance/comfyq_paths.py` (`COMFY_ROOT` env → `comfy_ui.root_path` from ComfyQ's config.json → legacy sibling layout), so they are drive-letter-independent and work from anywhere in the repo. **They are admin-panel buttons**, not console habits: `server/maintenance/scriptRunner.js` holds a WHITELIST of task keys (never a script path from a browser) and runs them through a `runpy` bootstrap, because ComfyUI's embedded Python has a `python312._pth` that pins `sys.path` and ignores `PYTHONPATH` — see [[embedded-python-pth]]. Current tasks: rebuild/verify the model audit, repair the install, portablize paths, and **`fix_custom_node_patches.py` — re-apply the custom-node fixes** (2026-10-08). **Fixed 2026-11-05:** `repair_all.py` and `portablize_paths.py` now use `comfyq_paths`, `REPAIR.bat` gets its interpreter from `python-path.js`, and `REPAIR.bat --check` runs from the repo. (Before that fix they built `<their own folder>\..\ComfyUI_windows_portable` and the two buttons were inert.)

**★ When adding a re-apply fix, three rules it must follow** (all paid for on this fleet): **idempotent** — these are buttons and get pressed twice, so a second run must say "already applied"; **it must REFUSE loudly with exit 1** when the target code is not what the patch expects, naming the anchor, because a repair step that silently matches nothing reports success over a machine it did not fix; and **parse the result before writing it** (`ast.parse`), so a bad edit cannot break ComfyUI's next import. ⚠ A patched pack then reads as **dirty** to git, which is correct — ComfyQ's node-pack updater refuses to pull over uncommitted changes, so a local fix cannot be silently discarded by an update. To update such a pack on purpose: commit or stash in the clone, pull, then press the button again.
