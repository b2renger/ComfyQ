Added two image-to-3D ComfyUI node packs to the portable NVMe ComfyUI (2026-07-07): **Saganaki22/Pixal3D-ComfyUI** and **visualbruno/ComfyUI-Trellis2**. Both rely on pre-compiled CUDA kernels locked to an exact `{OS, py-ABI, torch, CUDA, GPU-arch}` tuple.

**Key decision — downgraded torch 2.9.1 → 2.8.0+cu128** (from the start, owner's call). 2.8.0 is the only version with complete prebuilt Windows cp312 wheels for **both** packs; it keeps full Blackwell sm_120 support (RTX 5090 / A6000 Pro) and doesn't move the driver floor. Also installed: torchvision 0.23.0, torchaudio 2.8.0, **triton-windows 3.4.x** (must match torch 2.8). Ampere (3090/A6000) is **out of scope** — the shipped wheels are sm_89-based and won't run on sm_86.

**Kernels** (torch-2.8-matched, `--no-deps`): `cumesh`/`flex_gemm`/`o_voxel` from visualbruno's `wheels/Windows/Torch280` serve **both** packs; `drtk`+`flash_attn 2.8.3` from PozzettiAndrea/cuda-wheels (`+cu128torch2.8`). ⚠ These wheels are **no longer archived on the drive** (the `_wheels_torch28_cu128` folder is gone, checked 2026-11-05) — fetch them again from visualbruno `wheels/Windows/Torch280` and PozzettiAndrea/cuda-wheels if a reinstall is ever needed. The installed stack itself still matches (torch 2.8.0+cu128, triton_windows 3.4.0.post21, flash_attn 2.8.3+cu128torch2.8). `o_voxel` also needs `zstandard`. **natten skipped** (optional, no Windows wheel).

**★ RMBG / `auto_remove` fix (2026-07-07):** with `load_rembg=True` + `background_mode=auto_remove`, Pixal3D crashed in `transformers 4.57` with `'Config' object has no attribute 'get_text_config'`. Cause: the RMBG-2.0 `birefnet.py` sets `self.config = Config()` (BiRefNet's own plain training-config class, NOT `PretrainedConfig`), and transformers' `tie_weights()` now calls `config.get_text_config()`. **Fix:** added to `class Config` in `models/Pixal3D/briaai_RMBG-2.0/birefnet.py` a `tie_word_embeddings = False` class attr + `def get_text_config(self, decoder=False): return self`. Then **cleared the stale trust_remote_code cache** at `%USERPROFILE%\.cache\huggingface\modules\transformers_modules\briaai_RMBG_hyphen_2_dot_0` (transformers copies remote code there per-machine — a C: cache that regenerates from the NVMe model on any machine; redirect via HF_HOME). **Verified**: `auto_remove` now runs end-to-end → textured mesh. The fix lives in the model file on the NVMe (distributable), but is **lost if the model is re-downloaded** — re-apply then.

**★ Scope note**: keep changes to `custom_nodes/` + `models/` only. I once wrongly edited the `run_nvidia_gpu*.bat` launchers and ComfyQ's `comfyProcess.js` (cache env vars) — the owner flagged it; both reverted. Don't touch launchers/ComfyQ code for this.

**★ TRELLIS2 `to_resolution` COMBO fix (2026-07-07):** MeshWithTexturing/MeshOnly examples failed prompt-validation with `Value not in list: to_resolution: '1024' not in [1024, 1536]` (and GUI "value 1024 not available"). Cause: `Trellis2ShapeCascadeGenerator` + `Trellis2ShapeCascadeMultiViewGenerator` declared **integer** COMBO options `([1024,1536],{"default":1024})`, but ComfyUI's frontend coerces COMBO values to **strings** — so it sends/loads `"1024"`, which fails the strict int-list check. **Fix in `custom_nodes/ComfyUI-Trellis2/nodes.py`:** options → `(["1024","1536"],{"default":"1024"})` (2 defs, lines ~4187/6376) + cast `int(to_resolution)` at the two `self.sample(...)` call sites (~4238/6435). Also converted `to_resolution` (widget index 1) from int→string in the 7 example workflows. **Verified**: string value validates + full MeshOnly generation → valid mesh. **★ Reverts on pack update** (nodes.py) — re-apply. General rule: ComfyUI numeric COMBOs must use string options + cast, never int options.

**★ TRELLIS2 `resolution` COMBO fix (2026-07-08):** the **same** numeric-COMBO bug on a different widget — MeshWithTexturing failed with `Value not in list: resolution: '512'/'1024' not in [512,1024]/[128,256,512,1024,2048]/[512,1024,1536]` on `Trellis2ShapeGenerator` / `Trellis2ReconstructMeshWithQuad` / `Trellis2MeshTexturing`. There are **11** `resolution` int-combos in `nodes.py` (those 3 + the MultiView/TexSlat/Remesh/MeshRefiner/OvoxelExport/TrimeshToVoxel siblings), all latently broken. **Fix:** the 3 int lists → string equivalents, and `resolution = int(resolution)` inserted as the **first line of each `process()`** (the value is compared with `== 512`/`== 1024` and, for ShapeGenerator, **returned as an `INT` output** consumed by ShapeCascadeGenerator's `from_resolution` — so it must stay int downstream). Did **NOT** edit the example `.json`s: values are stored as ints there but the frontend submits them as strings (matches the fix), and a by-value JSON edit would corrupt neighbours (e.g. MeshTexturing's `texture_size=2048` sits beside `resolution=1024`). Applied via a re-runnable script saved **off-pack** (survives updates), now at `ComfyQ/tools/maintenance/fix_resolution_combos.py` (moved from `<nvme>\_maintenance\` 2026-10-06, see [[portable-no-drive-letters]]) (11 decls + 12 casts — the 12th is `Trellis2DecodeLatents`, an INT input → harmless no-op; `py_compile` clean). **Reverts on pack update — re-run the script.** Requires a **ComfyUI restart + browser hard-refresh** (INPUT_TYPES read at registration; frontend caches `/object_info`). **Consolidated (2026-07-08):** `fix_resolution_combos.py` was extended to **also** restore the `to_resolution` fix (so it fully repairs `nodes.py` in one pass — no longer just `resolution`), and both it and a rebuilt `portablize_paths.py` (example-workflow paths) + the `notice.md` doc were made **drive-letter-independent** and moved into the durable **`<nvme>\_maintenance\`** hub — since 2026-10-06 that hub is `ComfyQ/tools/maintenance` in the repo; see [[portable-no-drive-letters]] for the folder convention + run command.
