## How the machine runs

- **Two modes.** Admin mode schedules nothing; student mode serves. `server/data/.serving` makes a restarted machine resume serving; *Reset to admin* and emergency stop clear it.
- **ComfyUI outlives ComfyQ, on purpose.** [comfyLauncher.js](server/workers/comfyLauncher.js) starts it through PowerShell `Start-Process` with output in `.comfyq-lanes/logs/`, records port → PID, user dir and flags in `.comfyq-lanes/processes.json`, and [ComfyProcess](server/workers/comfyProcess.js) adopts it on the next start. It survives Ctrl+C: stop it from the admin panel. 5 unexpected exits in 15 min pause respawning for 10 min.
- **A reused ComfyUI is checked against current settings.** [launchSettings.js](server/workers/launchSettings.js) compares its argv with what the lane would start: a flag that would break output relaunches it whoever started it; any other difference relaunches only a ComfyUI ComfyQ started; no difference, no restart.
- **Lanes.** A lane = one workflow + its own ComfyUI + its own executor ([laneManager.js](server/lanes/laneManager.js)). "Base" is where it runs (the install's ComfyUI); "main" is `activeWorkflowId`. Any lane can close while others serve. *Activate & serve* while serving is a live switch on the warm ComfyUI. Closing a lane stops its running job. Admission uses the measured VRAM peak, which only goes up while the graph stays the same; the static estimate is wrong by more than the slack on a 32 GB card.
- **Per-workflow perf flags.** `requirements.disabledPerfFlags` masks Sage or fp16 accumulation for bundles that save black images under them, at serve and at calibration.
- **Restart during a job:** the job fails with `server-restart` and its prompt is cancelled in ComfyUI, on every lane, by id. A finished result is not collected.
- **Another install on the port:** a hand-started ComfyUI from another install is refused and left running; the reason shows at the top of the admin panel (`server/data/.serve-error`). The port is a startup option, locked while serving.
- **Passwords.** The admin password gates every `/admin` route that changes something (Activate & serve included) and fails open when unset. The access password is separate: it reserves a machine, through the socket handshake and `/jobs` + uploads. Neither covers ComfyUI's own port.
- **Test suite.** [library.suite.json](tools/test-suite/library.suite.json) runs every card once at its defaults, in stages that reuse earlier outputs. A missing input skips the run with the reason. Each run is a valid calibration. Run from the CLI (`run-suite.cjs`) or the sweep card; `seed_examples.cjs` turns the report into examples. `server/lanes/lanes.integration.js` needs real ComfyUIs and is run by hand.
- **Storyboards.** A markdown document becomes a batch of jobs ([docs/storyboard-format.md](docs/storyboard-format.md), [server/storyboard/](server/storyboard/)). ⚠ Only the first workflow's shots run today (question 11).
- **Card text layers.** `title` + `summary` are plain words, `name` is the model, `description` is technical. Student pages and Discovery lead with the title; the admin panel leads with the name.

## Runtime / environment
- **Node: LTS only.** Currently **Node 24 "Krypton"**, pinned in [.nvmrc](.nvmrc) (`24`) with `engines.node` = `^22.0.0 || ^24.0.0` in the root, [server](server/package.json), [client](client/package.json) and [desktop](desktop/package.json) `package.json` (was `>=22.0.0 <25.0.0` until 2026-11-05, which let Node 23 through without a warning; now 23 warns). Odd-numbered "Current" releases (23, 25, …) are unsupported — the lab runs varied machines and needs an LTS line. When Node 26 becomes LTS (~Oct 2026), bump `.nvmrc` + the four `engines` ranges (⚠ 2026-11-05: that date has passed; allowing `^26` is the owner's call, not done).
- **Windows winget gotcha:** winget ships Node as two packages. `OpenJS.NodeJS` is the **wrong** (Current) one; use **`OpenJS.NodeJS.LTS`**. To swap: `winget uninstall --id OpenJS.NodeJS --exact` then `winget install --id OpenJS.NodeJS.LTS --exact` (needs admin; globals in `%AppData%\npm` survive).
- **`better-sqlite3` is the only native dep**. v12+ downloads a prebuilt binary per Node ABI (no compile on supported platforms), but the binary is tied to the Node major version that installed it. After any Node *major* change, wipe `node_modules` and `npm install` so the ABI matches.

## Serving model — plain HTTP (do NOT re-add HTTPS)
- The dev/workshop UI is served over **plain HTTP** (Vite on :5173, proxying the Express backend). The self-signed HTTPS layer (`@vitejs/plugin-basic-ssl`) was tried and **reverted 2026-05-19**: self-signed certs can't be trusted across BYOD Safari + Chrome + mobile without installing a CA on every device, and Safari refused to extend a click-through to the websocket and to media downloads.
- **Don't reintroduce `@vitejs/plugin-basic-ssl` or `https: true`** in [client/vite.config.js](client/vite.config.js). The only feature it enabled — in-browser webcam capture (`getUserMedia`, needs a secure context) — was removed; image/video inputs are uploaded as files (a phone's file picker still offers "Take Photo").
- **Secure-context APIs don't work off-localhost over plain HTTP** — anything gated on `window.isSecureContext` (`navigator.clipboard`, `getUserMedia`, …) is unavailable on `http://<lan-ip>`. For clipboard, use [client/src/utils/clipboard.js](client/src/utils/clipboard.js) `copyToClipboard()` (tries the async API, falls back to a hidden-`<textarea>` + `execCommand('copy')`); never call `navigator.clipboard.writeText` directly.

## Key implementation patterns

**Workflow registration:** Each workflow is a folder bundle: `workflows/<id>/<id>.api.json` (the ComfyUI API-format export) + `<id>.meta.json` (parameters, description, category). The admin metadata editor and the Validate button rewrite `<id>.meta.json` itself (`PUT /admin/workflows/:id/meta`, `PUT /admin/workflows/:id/experimental`), so admin edits are committed with the bundle. The registry still merges an optional `<id>.config.meta.json` (per-field label/default/order/enabled overrides, `hidden`), but only the unused `PUT /workflows/:id/config-meta` writes it, and nothing in the UI calls that route. (Corrected 2026-11-05: this used to say meta.json is read-only and the UI writes `.config.meta.json`; the editor has saved through `/meta` since 2026-05-03.) **Every bundle ALSO ships `<id>_template.json`** (the ComfyUI **UI/litegraph** graph — subgraphs, groups, notes, layout), beside the api.json; **this is required, not optional** (enforced by [bundleCompleteness.test.js](server/workflows/bundleCompleteness.test.js) in `test:storyboard`). A bundle built api-first gets one from [tools/api-to-ui/convert.mjs](tools/api-to-ui/README.md). It's detected by the registry (`entry.hasTemplate`/`templatePath`) and, when present, the admin editor's **Open in ComfyUI** hands *it* over (a fully editable graph) instead of the flat API graph — see the "Open in ComfyUI — template = editable graph" pattern below. It's **not parsed** (the parser only understands API format) and is purely for round-tripping the graph back into the ComfyUI editor.

**Open in ComfyUI — template = editable graph (auto-open):** The admin editor ([WorkflowMetaEditor.jsx](client/src/components/admin/WorkflowMetaEditor.jsx)) and the per-card button in the admin library ([WorkflowSelector.jsx](client/src/components/WorkflowSelector.jsx)) both boot ComfyUI (auto-launch the admin backend if down) and hand the current workflow over for editing, via the shared hook [useComfyOpener.js](client/src/hooks/useComfyOpener.js). **ComfyUI 1.45 has no URL param to open an arbitrary workflow**, and its startup tab-restore is **browser-localStorage per-clientId** (not server-writable), so we ship a **tiny opener extension** ([server/comfyui/opener/](server/comfyui/opener/), auto-installed into `<comfy root>/custom_nodes/comfyq_opener` by [openerExtension.js](server/comfyui/openerExtension.js), as a versioned `js/comfyq_opener_v<OPENER_VERSION>.js` so a bump is a new URL) that reads a custom **`?comfyq_open=<id>_template`** param and `loadGraphData`s the staged workflow onto the canvas. Flow: `openInComfy(id)` → `POST /admin/workflows/:id/open-in-comfyui` (stages the template as `<user dir>/default/workflows/<id>_template.json` — the user dir is a served lane's own `--user-directory`, otherwise `<comfy root>/user` — **and** `adminCalibrator.ensureOpenerLoaded()`, which launches/one-time-restarts ComfyUI so the opener is loaded) → the tab opens `<comfyui>/?comfyq_open=<id>_template` and the graph loads itself. (Corrected 2026-11-05: this pattern said `<id>.json` and `?comfyq_open=<id>`; staging under `<id>.json` overwrote an admin's own hand-saved workflow and was renamed on 2026-07-01 b.) **Fallbacks:** `autoOpen:false` (external ComfyUI we can't restart) → open ComfyUI + tell the admin to pick it from the **Workflows sidebar** (the template is still staged); 409 (no template) → download the file to drag on the canvas (UI → editable graph; API → flat via `loadApiJson`). The older `stage-template` route is a harmless subset of the new one. `GET /admin/workflows/:id/edit-data` returns `templateWorkflow` (read fresh from `templatePath`) + `hasTemplate` next to `apiWorkflow`, and `hasTemplate` is on the `/workflows` summary too. **Template detection tolerates filename variance** — the registry falls back to any `*template.json` in the folder (not just `<id>_template.json`) as a defensive net; the bundles are all now on the canonical `<id>_template.json` name. The template is **display/round-trip only** — it never touches param detection (which needs API format) or job execution (the api.json still runs). Staging overwrites `<id>_template.json` each click; an admin's own `<id>.json` is never touched (our bundle template is the source of truth; edit in ComfyUI → re-export back into the bundle to persist). *(The sibling per-card **"Activate & serve"** button — `activate(id)` → student mode — lives in the same card row; see the 2026-07-01 progress entry.)*

**Output detection (generic):** No `class_type` whitelist. [server/media/mediaTypes.js](server/media/mediaTypes.js) classifies by file extension (`KIND_BY_EXT`): `.png/.jpg/.jpeg/.webp/.bmp/.gif` → image, `.glb/.gltf/.obj/.fbx/.ply` → model3d, `.spz/.splat/.ksplat` → splat, `.mp3/.wav/…` → audio, `.mp4/.webm/…` → video, `.json` → json, anything else → binary (served as a download). Collecting and serving a new output format needs no `class_type` change, but a new extension only renders in a viewer once it is added to `KIND_BY_EXT` (a `.tif`/`.avif`/`.exr` reads as binary today). (Corrected 2026-11-05: this used to say "else image" and "no code changes needed".) A node that saves a file but reports it only as an absolute-path string, in any output key (Pixal3DExportGLB's `text`, Preview3D's `result`), is also collected: [outputCollector.js](server/executor/outputCollector.js) `_collectMediaPaths` serves any single-line absolute path to an existing file under the output or temp dir, classified like any other output, and `_collectText` skips such strings.

**Subfolder serving:** ComfyUI save nodes write to subfolders (e.g., `SaveAudioMP3` → `audio/track.mp3`). The wire carries the full output-root-relative filename; [server/executor/jobExecutor.js](server/executor/jobExecutor.js) folds the subfolder into `filename` and clears the `subfolder` field so `/images/:filename(*)` serves them without breaking existing routes.

**Multi-output galleries:** When a job produces >1 image, the lightbox renders [ImageGallery.jsx](client/src/components/ui/ImageGallery.jsx) (main image + thumbnails + prev/next). When it has both a splat and a mesh, a toggle switches between the 3D viewers. Audio outputs render the AudioPlayer. The Scheduler grid shows a "{N} views" badge for multi-output jobs.

**Student param form is ONE shared component (`DynamicParamFields`):** [client/src/components/DynamicParamFields.jsx](client/src/components/DynamicParamFields.jsx) renders the exposed-parameter form from a `parameter_map` and is the single source of truth for how students see inputs. It's rendered by **both** [BookingDialog.jsx](client/src/components/BookingDialog.jsx) (the real booking, with live state) **and** the admin [WorkflowMetaEditor.jsx](client/src/components/admin/WorkflowMetaEditor.jsx) "Student preview" (throwaway state) — so the admin's preview can never drift from production. Props: `paramMap`, `values`, `onValueChange(key,value)`, `mediaPreviews`, `recalledMedia`, `mediaChangeHandler(key)→(file)→void`, `mediaRemoveHandler(key)→()→void`. The editor preview converts the editor's param-array (`nodeId`, `enabled`, …) into the wire `parameter_map` shape (key→{type,label,default,options,min,max,step,disabledWhen,required,field,order,enabled}); `field` is needed because seed detection (`isSeedParam`) keys off it. **If you add a new param *type*, add its branch here once** and both the booking form and the preview get it. **Prompt boxes (textarea params, 2026-09-15)** open at 208 px (104 px when the key/label says "negative"), are vertically resizable (72 px – 70vh), and remember the height a student drags to in `localStorage` (`comfyq.promptBoxHeight.prompt|negative`, per browser); the booking dialog is `max-w-2xl` so long prompts get width too. Keep `transition-colors`, not `transition-all`, on a resizable textarea — a height transition makes the drag lag.

**Param field gating (`disabledWhen`):** A parameter can declare `disabledWhen: { param, equals }` in the meta to grey itself out when another param holds a value. Used for either/or prompts (raw vs. LLM-enhanced). The field still submits; the workflow's switch node ignores the unused branch. **Preserved through the editor (2026-06-26):** `edit-data` returns it and the editor's save payload re-sends it, so an admin open+save no longer drops a workflow's gating (there's still no UI to *edit* `disabledWhen` — it round-trips untouched).

**Mask-draw input (`mask` param type):** For inpainting, a param `type: "mask"` renders [MaskDrawField.jsx](client/src/components/capture/MaskDrawField.jsx) instead of an uploader: the user picks a base image and **brushes the region to replace** in a **near-fullscreen paint modal** (`createPortal` to `document.body` so it escapes the booking dialog's transform/stacking context — the canvas fills the viewport for precise masking; the form shows a small composited preview + a "Paint/Edit mask" button), and the component composites it into a single RGBA PNG where the painted area is **transparent** (`globalCompositeOperation='destination-out'`). ComfyUI's `LoadImage` derives `MASK = 1 − alpha`, so transparent → mask 1.0 → "inpaint here" — one file feeds both the image (out 0, RGB) and the mask (out 1). The produced File flows the **same** path as an image upload (`onChange`→`handleMediaChange`→`/upload`→generic materializer), so the server is untouched. `mask` is treated as `image` everywhere the value flows: it's in `MEDIA_TYPES` (BookingDialog), required-by-default + `inferType` (parser), `maxInputEdge` (meta editor), and calibration stages a plain image for it (no alpha → empty mask → no-op inpaint, still runs the sampler → valid timing). Brush colour is cosmetic only (export reads alpha; recolour is `source-in`). Adding the type means editing both the zod enum ([schemas.js](server/config/schemas.js)) **and** the duplicated `PARAM_TYPES` array in WorkflowMetaEditor — they aren't shared. **Mask polarity** is the standard ComfyUI convention (white = inpaint, the graph's `mask_invert:false` confirms); flip in `MaskDrawField.commit()` if a rig run inpaints the inverse.

**Dynamic dropdown params (`lora` type):** A param `type: "lora"` renders a `select` whose options are populated **server-side at booking time**, not baked into the meta. [modelOptions.js](server/workflows/modelOptions.js) `listModelFiles(comfyRoot, subdir, prefix)` scans `<comfy root>/models/<optionsDir|'loras'>` on the ComfyQ host's disk (not via ComfyUI's API — works whether ComfyUI is up or not), keeps weight files whose name starts with the `optionsFilter` prefix (e.g. `krea2_` → only Krea-compatible LoRAs), sorts, and TTL-caches (8 s — the realtime bus rebuilds the parameter_map on every broadcast). [realtimeBus.js](server/realtime/realtimeBus.js) `_buildParameterMap(exposed, comfyRoot)` sets `options` + prettified `optionLabels` (extension stripped) for `lora` params, always keeping the `default` selectable so the field never renders empty (off-rig or missing dir → just the default). The wire value is the plain `.safetensors` filename, so the **generic materializer / recall / calibration treat it like any string** — only the widget differs (shared `select` branch in [DynamicParamFields.jsx](client/src/components/DynamicParamFields.jsx), which reads `optionLabels`). `optionsDir`/`optionsFilter` live in meta.json and **round-trip through the editor** (save payload + edit-data merge, like `disabledWhen`); the base meta owns the `type` (config-overrides only patch label/default/order/enabled). The admin "Student preview" fetches the same list from `GET /admin/loras?dir=&filter=`. To offer a different model family/dir, set `optionsFilter`/`optionsDir` in the meta — **no code change**. Adding the type touched the zod enum ([schemas.js](server/config/schemas.js)) **and** the duplicated `PARAM_TYPES` array in WorkflowMetaEditor (not shared). First used by [image_krea2_turbo_t2i_lora](workflows/image_krea2_turbo_t2i_lora/).

**Text outputs (LLM / caption):** Nodes that emit text instead of a file (`PreviewAny` "Preview as Text", `ShowText`, …) report a `text`/`string` array in `history[promptId].outputs`. `_collectText` in [server/executor/outputCollector.js](server/executor/outputCollector.js) collects these as a `kind:'text'` output with the string **inline on the wire** (no file to serve); [server/executor/jobExecutor.js](server/executor/jobExecutor.js) forwards `o.text`, and `ImageLightbox`/`MediaPreview` render the caption. No `class_type` coupling — any text-emitting node Just Works, so image/video→text workflows (Gemma describe-it) land zero-code. First exercised by the Gemma 4 captioners. Beside a media output, text with no whitespace is treated as plumbing and dropped (`_keepResultText`, df72046). When text is all the run produced, it is kept whatever it looks like. So a node that answers with a single token next to a picture never reaches the student.

**Friendly failure messages (`humanizeFailure`):** ComfyUI execution errors reach the user as the job's failure `reason`, computed at two sites — the WS `execution_error` event ([localComfyUIWorker.js](server/workers/localComfyUIWorker.js)) and the history-status fallback ([jobExecutor.js](server/executor/jobExecutor.js)); both carry the failing node's `class_type`. `humanizeFailure(message, nodeType)` in [errorMessages.js](server/executor/errorMessages.js) rewrites known signatures into actionable text (first case: no-face on a face-cropper node → "upload a clear photo with a single, fully visible face"), and **falls through to the raw message** for everything else (errors are clarified, never swallowed). Add new mappings here, not at the call sites. Keep guards tight (e.g. an OOM on a face node is *not* a no-face problem) to avoid mislabeling.

**Experimental bundles:** a newly promoted workflow ships `"experimental": true` in its meta.json; the admin library badges it and the **Validate** button clears it (`PUT /admin/workflows/:id/experimental`, writes meta.json itself so the sign-off is committed). Purely a label — experimental bundles calibrate and serve normally. **Promotion recipe for future candidates:** convert with [tools/ui-to-api/convert.mjs](tools/ui-to-api/convert.mjs) (ComfyUI's own `graphToPrompt`, never by hand), keep only final-result outputs, rewire in-path preview passthroughs, validate params against `/object_info`, calibrate, **then check the output content** (a black image still reports success).

**Perf-flag opt-out (`requirements.disabledPerfFlags`):** the rig-wide `use_sage_attention` / `fp16_accumulation` speed-ups can make a model save black images without any error (Qwen-Image-Edit + Sage; SeedVR2 7B int8 + fp16 accumulation). A bundle lists the flags it can't run with; [perfFlags.js](server/workers/perfFlags.js) masks them for the ComfyUI that serves (student boot, which also replaces a running ComfyUI that has them) or calibrates (AdminCalibrator) that workflow. Diagnose a black output by toggling one flag at a time before blaming the graph.

**Optional image inputs (`required: false` on an image/mask param, 2026-09-14):** until now every media param was mandatory — the booking form ignored `required` and **returned silently** when an upload was missing (the owner's "Start does nothing" on `utility_ltx2_5_video_deblur_upscale`, whose optional start image was still `required: true`). Image/mask only — there is no neutral placeholder video/audio. **A `whenEmpty: "unlink"` slot is never placeholder-filled** — it is taken out of the graph instead, and `unlink` / `whenEmptySet` judge emptiness on the booked values, not the filled ones (2026-11-05; before that the fill ran first and neither ever fired in a real submit). Applied to the deblur and `video_edit_ltx2_5_iclora_union_control` start images (toggle moved above the image field). Verified end to end on the rig: a socket-booked deblur job with no start image at 1088 px completed (1088² video with the original audio); the switched-on case fails at submit. Tests: `node server/workers/optionalMedia.test.js` (in `test:storyboard`).

**Collector skips inputs and de-dupes paths:** [outputCollector.js](server/executor/outputCollector.js) ignores `type:'input'` records (LoadVideo previews its upload) and doesn't re-collect a file pass 1 already found via an absolute `fullpath` (VHS_VideoCombine).

**Calibration (auto, single run split into load+gen, admin-mode):** [server/benchmark/benchmarkService.js](server/benchmark/benchmarkService.js) runs the workflow **once** (explicit `/free` first so models load) and splits the run at the first sampler `progress` event: start→first-step = `modelLoadSec`, first-step→end = `estimatedDurationSec`/`warmDurationSec` (the recurring/optimal cost the timeline uses); full wall time = `coldDurationSec` (first-run incl. load); plus `samplesPerSec`, `gpu` and the measured VRAM (`vramPeakGb`, `vramResidentGb`, `vramCardPeakGb`). **Do NOT add a second "warm" run** — ComfyUI caches identical graphs and returns the cached result in ~1s, which made calibration report 1s for a 25s job (regression fixed 2026-06-13). Instead `_randomizeSeeds()` bumps every literal `*seed` node field **and** `_buildCalibrationParams` randomizes every exposed seed param, so the single run always actually executes (cache-immune, even on re-calibration). Inputs **auto-resolved from `config.assets.dir`** (`D:\_assets`): `_resolveAsset(type)` picks a median image or mesh / smallest video or audio clip, staged via the worker's `InputUploader` (image falls back to a built-in PNG; missing video/audio asset → clear error). When content matters (a person to track, a face, a sound track), set the media param's `warmupParams` value to **`asset:<file name in the assets dir>`** to stage that exact file (2026-09-14). **The load/generation split assumes the first progress event is the first sampler step** — a node whose progress bar counts tiles or frames (PiD's `LatentTiledPiDDecode`) bills its first unit as model load and under-reports the warm time; measure those by hand (see `utility_pid_image_upscale`). Gauge button works in **admin mode** via [server/benchmark/adminCalibrator.js](server/benchmark/adminCalibrator.js) (lazily spawns/attaches ComfyUI, reuses it, idle-frees VRAM, leaves ComfyUI running on shutdown). **No UI, no uploads.** In student mode it runs on the workflow's own lane, else the main lane, and is refused while that worker is busy or when its ComfyUI runs a flag the bundle disowns (`disabledPerfFlags`). **Config freshness (2026-06-21):** `AdminCalibrator` reads ComfyUI paths **fresh from `configManager` on each launch/calibrate** (getters, not a boot-time snapshot), so a path saved in Settings is honored immediately by the gauge and the *Launch ComfyUI on the network* button; it restarts a ComfyUI it spawned when the saved paths change (don't reintroduce a constructor snapshot — that was the "launch ignores my new path" bug).

**Image upload guard:** Three-layer protection against OOM crashes from oversized images: (1) client throws `ImageProcessError` on HEIC/decode failure; (2) [MediaCaptureField.jsx](client/src/components/capture/MediaCaptureField.jsx) shows inline error; (3) [server/routes/uploads.js](server/routes/uploads.js) backstop rejects HEIC (extension + ftyp magic byte) and images not fitting 1920×1080 box in either orientation. Server uses `image-size` library (pure JS, no native dep).

**Light-theme color tokens:** Theme is class-based (`.dark`/`.light` on `<html>`) over CSS-var tokens in [client/src/index.css](client/src/index.css) (`@theme` → `--color-*`). A compat hack maps **`--color-white → --text`** so the ~150 existing `text-white` usages stay readable in light mode without a sweep. The gotcha: that makes `text-white`/`bg-white` on a **solid accent fill** (`bg-primary`, `bg-danger`, …) dark-on-dark in light mode. For text/icons/knobs on an accent fill use the **`--color-on-primary`** token (`text-on-primary`/`bg-on-primary`) — it stays light in both modes. New surfaces should prefer `bg-background`/`bg-surface` + `text-foreground`/`text-muted`, not hardcoded slate/black/white.

**Input retention & asset reuse:** Booked-job media uploads go to `<comfy>/input/comfyq_session__*` and the filename is stored in `job.paramValues` (so it's on the wire). The periodic `sweepStale()` ([inputUploader.js](server/workers/inputUploader.js)) deletes `comfyq__` (job-scoped, execution-time) files after `queue.inputRetentionMinutes` (30 min) and `comfyq_chain__` files (a storyboard's intermediate frames) after 24 h. It never touches `comfyq_session__` uploads or `comfyq_placeholder.png`, so the original uploads persist. "Use these settings" exploits this: [BookingDialog.jsx](client/src/components/BookingDialog.jsx) re-binds the recalled filename directly (no re-upload; the materializer injects it) and previews/plays it via `GET /input-media/:filename` ([uploads.js](server/routes/uploads.js), restricted to the `comfyq_` prefix + pinned inside the input dir).

**ASAP booking:** A booking with no slot picked sends `scheduledTime: null`; the server treats null-or-past as ASAP and schedules into the earliest non-colliding slot via `jobQueue.nextFreeSlot(now, durationMs, workflowId)` (a greedy walk over the booked workflow's unfinished jobs only; lanes run in parallel, so another workflow's jobs are never in the way) instead of throwing a collision. An explicit future time keeps the `findCollisions(…, workflowId)` guard, scoped the same way (see 2026-10-16: unscoped, two lanes took turns). Unscoped calls (the storyboard's `latestActiveStart`) keep the whole-machine answer. `findReady` orders by `scheduled_at ASC, created_at ASC` (FIFO tiebreaker). The BookingDialog's segmented **ASAP / Pick-a-time** toggle drives `scheduledTime` (null vs a timestamp).

**Prompt display resilience:** `pickHeadlinePrompt()` in [BookingDialog.jsx](client/src/components/BookingDialog.jsx) finds the user's text at submit time (prefers textarea params, skips negative-keyed ones). `getDisplayPrompt()` in [jobDisplay.js](client/src/utils/jobDisplay.js) mines `job.params` at render time so historical jobs display even if exposed under non-`prompt` keys (e.g., LTX `positive_prompt`, Ideogram `description`).

## Federation (Phase F — F1+F2 shipped via beacon + packaged auto-updating desktop app, in user testing 2026-06-28; F3–F6 deferred)
The final v2 phase is multi-instance LAN federation. **The first slice shipped (2026-06-27→28)** as a **UDP multicast status beacon** + a standalone **Electron fleet monitor** (`desktop/`) — now packaged as a self-updating installer (see the "Desktop app — installers + GitHub auto-update" Latest-progress entry) — a deliberate divergence from the originally-locked mDNS/in-browser-panel design — see the Latest-progress entry above and [implementation_plan.md](implementation_plan.md) → "Phase F". Server code lives under [server/federation/](server/federation/); the beacon and `GET /federation/self` share one `buildSnapshot()`. **Conventions to keep:** beacon transport is built-in `dgram` UDP multicast (no mDNS dep added); federation is **on by default** but fully gated by `config.federation.enabled` so a disabled boot is byte-for-byte today's single-instance behavior; the new `config.instance`/`config.federation` schema blocks are **optional/defaulted** so existing `config.json` validates unchanged. The remaining locked design (mDNS, cluster-secret auth, cross-instance admin actions, AdminConfig panel, student station picker, orchestrator role) stays deferred. **Implication for other work:** don't bake in single-instance assumptions — if a feature surfaces state that should be aggregable across peers, expose it where `buildSnapshot()` / a future `/federation/*` route can return it without a schema migration.

## Conventions

One line each; the story behind every rule is in PROJECT-HISTORY.md.

**Working here**
- Commit or push only when the owner asks. Work sequentially; no multi-agent workflow unless the owner asks for one in that request, with its cost stated first.
- ★★ **Never edit `server/` while a long job runs.** nodemon restarts ComfyQ and clears in-memory state; it killed a sweep at bundle 32 of 61, and again at 37. The edit always feels too small to matter.
- ★★★ A rule you wrote does not protect you: the guard has to fire at the moment of the action.
- ★★★ Silence is only information if the silent path is the one you tested. A check that cannot run looks like a check that found nothing: no discarded stderr, loud failure, a fixture run first.
- ★★ Every fix pass creates new text and code to review. Raise the bar and stop; do not loop until the count is zero.
- ★ A reviewer's count is a claim too. Check a summary's numbers against the code before writing them down.
- ★★ A doc that rests on an external blocker needs a date, a re-check command, and something that runs it.
- ★★ The frame where an error is raised is not evidence of which component is wrong; a traceback that names a new feature gives a suspect, not a cause. Re-run before believing a fix.

**Bundles and cards**
- **API-format workflows only.** Output detection is generic, by file extension, never by `class_type`.
- ★ Two files per workflow, always: `<id>.api.json` and `<id>_template.json` ([tools/api-to-ui](tools/api-to-ui/README.md) makes one). `test:storyboard` fails otherwise.
- ★ Every declared model says where it comes from (`url`, `source` or `auto`), via [tools/model-provenance](tools/model-provenance/README.md). Never hand-write a direct `url`. ★★ A link that answers is not a link that is right.
- ★ An api literal is what every unattended run uses: keep it equal to the card's default.
- ★★★ A calibration warmup must run the card's DEFAULT job, on an input of realistic size. A cheaper run is another measurement and must not write `runtime.json`.
- ★★★ A timing measured on an unopened output is not a measurement. Run `output_stats.py`, and open the picture.
- ★★★ A caption is a claim about the result: write it after looking (and listening). A vendor's claim is a hypothesis on this rig.
- ★★ An optional media param that must change the graph uses `whenEmptySet`, not a visible toggle. When two nodes must agree, expose ONE control and link the other.
- ★★ A mandatory trigger token goes in the GRAPH, not in a default prompt.
- ★★★ A model's training resolution is not the resolution to feed its reference: when the output looks like the training data, the input is too thin to compete. ★★ An author's "recommended checkpoint" is recommended against the base they trained on; this fleet runs int8-convrot repacks.
- ★★ When a reference-conditioned model copies its reference, compare the reference with the vendor's example before tuning a setting.
- ★★ A control read frame for frame and written at a fixed rate re-times the clip: compare frame rate and cut times with the source.
- ★ A PreviewImage can be in the path since ComfyUI 0.43: prune by graph, not by class name. ★★★ Keep whatever reports a count when a node can silently return nothing.
- ★★ A new media type is finished when every place that ENUMERATES media knows it. Grep the literal list. A filter matches on extension when the type has no MIME family.
- ★ An ingredient for a multi-field param records the whole value. ★★ When one control feeds several fields, the mapping lives in the meta and the arithmetic is pinned to the authority.

**Safety tools**
- ★★★ A protection that cannot be lifted is a leak, not caution: a signal that guards a file must say what releases it.
- ★★★ In a REMOVAL an observed load proves nothing, since the only thing that opened the weight may be the thing being removed. "Nothing is exclusive" is a question: read WHICH signal protected the file. `observed during X` is a lead, never a verdict.
- ★★ "Only X uses this" must never be said from an observation that cannot see reuse.
- ★★ An interlock whose condition is derived from the danger it guards is not an interlock. A waiver comes from a deliberate act and drops when it stops applying.
- ★★ A destructive script must say whose files it acts on, and check it. ★★ What an operation spares is derived from what defines it, not from a pattern that resembles it.
- ★★ A cleanup script's job is residue, not tidiness: report anything it did not create, with a size, and leave it.
- ★★ An operation that deletes what a cache, a report or a copy describes owns the cleanup of all three. Before deleting a job, check whether its inputs are shared.
- ★★ A dated snapshot must not overrule a live check. A catch-all reason string in a safety tool is a defect.
- ★ A path that self-heals in three places of four is a trap: the fourth is the one nobody checks.

**Detectors and guards**
- ★★★ A refusal beats a confident wrong number.
- ★ A detector that fires on correct behaviour gets ignored. ★★★ But exempt the CASE, never the CATEGORY: widen what satisfies the check, never who may be accused.
- ★★ A guard must be satisfiable by the case it protects, and any conditional diagnostic needs a test that drives its condition.
- ★★★ A control in a measurement must be compared with what the failure would look like, not only with the expected result.
- ★★★ A hook on a shared function records every caller, including later ones: record in the context that gives the call its meaning. A guard keyed on WHEN is broken by anything simultaneous: key it on WHO.
- ★★ When one result feeds the next, a guard searching for a foreign token finds the upstream bundle's. Key ownership on the field that writes it. "Is this the same run?" must follow the chain.
- ★ Noise in a report is often a defect in the product. A matcher over source text matches the registration shape, not the word.
- ★ An operation that can change nothing says so in those words. Unknown and current are different answers: never conclude "up to date" from a failed fetch.

**Tests**
- ★★ A test must not be able to reach a real service, and must never write into `server/data`. Inject the directory and block the transport.
- ★ Fixtures carry what production carries: an unrealistic value can make a broken matcher pass for the wrong reason.
- ★★ A pure-looking function must not write shared state: its own test can replace the real file.

**Processes and Windows**
- ★★★ On Windows a child dies with its parent unless it has no live parent. Start long-lived helpers through an exiting intermediary, with output in files, found again by PID.
- ★★ A handle an intermediary passes on is a stream you are still waiting for: read results from a file and wait on its EXIT.
- ★★★ When a process outlives its launcher, every launch setting needs a check at reuse, in both directions.
- ★★ "Main" and "where it runs" are different properties of a lane. Ask the process what it has loaded; do not infer it from who started it.
- ★★ Python closures bind late: build wrappers in a factory. The embedded python ignores `PYTHONPATH`.

**Client and UI**
- ★★★ Never declare a component inside a render body: React rebuilds the DOM node and kills any interaction in progress.
- ★★★ A feature that is built, routed and tested is not shipped until something in the UI calls it.
- ★★★ A UI race is not tested by a fast machine: throttle the CPU. A UI check that does not scroll to its target measures the viewport.
- ★★ A field that looks governed by a shared Save button must be, or must not sit in that card. Where a feature goes is settled by where someone reaches for it; a card that renders as nothing while loading reads as never built.
- ★★ A failure is reported where the user is looking. Check "replaced", not "changed", before undoing anything on a user's screen, and stop when they act.
- ★★ A control that looks continuous but buckets must show its buckets.
- ★ "Unchanged" for a file another program re-saves is a graph comparison, not a byte comparison.
