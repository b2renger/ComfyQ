## Latest progress (2026-09-21)

**Parallel lanes — one machine serves several workflows at once, gated by a VRAM estimate (owner request, 2026-09-21)** — owner: *"see the admin panel and select a model to run in one instance… then connect to the admin and serve another model in another instance with parallel inference if it fits the vram"*, and *"we do not want to touch the comfy portable installation"*. `npm run dev` is unchanged; everything is driven from the admin panel. Branch `feature/parallel-lanes`.
- ★ **A lane = a workflow + its own ComfyUI + its own executor** ([laneManager.js](server/lanes/laneManager.js)). The first lane keeps the configured port and the install's own directories, so a single-lane machine behaves exactly as before; every extra lane gets the next port and **its own `--user-directory` / `--temp-directory` under `.comfyq-lanes/` at the repo root**. Both are mandatory, not tidiness: ComfyUI 0.37 takes an exclusive `FileLock` on `<user-dir>/comfyui.db` with `timeout=0` (a second process dies instantly) and **`rmtree`s its temp dir at startup** (`main.py:499`). The portable install is never written to — only extra command-line flags — and `models/` + all 47 custom nodes stay shared because `--base-directory` is deliberately NOT used. `--vram-headroom` asks each extra ComfyUI to leave room for its neighbours (its DynamicVRAM reads real free memory via NVML, so lanes negotiate rather than OOM).
- ★ **One lane per workflow** is the invariant that makes it safe: `queue.findReady(now, workflowIds)` now takes a filter and each lane's `JobExecutor` claims only its own workflow's jobs, so two lanes can never see the same row and no lease is needed. Booking a workflow that no lane serves is **refused at `book_job`** — it would otherwise sit SCHEDULED for ever, since no executor would claim it.
- ★ **VRAM estimate, per workflow, per machine** ([vramEstimate.js](server/workflows/vramEstimate.js), 16 tests). Sums the model files on the graph's **active path**, resolving `ComfySwitchNode` and following only the taken branch — its inputs are `lazy=True` and ComfyUI loads just the selected side (`comfy_extras/nodes_logic.py:86-116`). ## Runtime / environment
- **Node: LTS only.** Currently **Node 24 "Krypton"**, pinned in [.nvmrc](.nvmrc) (`24`) with `engines.node` = `>=22.0.0 <25.0.0` in the root, [server](server/package.json), and [client](client/package.json) `package.json`. Odd-numbered "Current" releases (23, 25, …) are unsupported — the lab runs varied machines and needs an LTS line. When Node 26 becomes LTS (~Oct 2026), bump `.nvmrc` + the three `engines` ceilings.
- **Windows winget gotcha:** winget ships Node as two packages. `OpenJS.NodeJS` is the **wrong** (Current) one; use **`OpenJS.NodeJS.LTS`**. To swap: `winget uninstall --id OpenJS.NodeJS --exact` then `winget install --id OpenJS.NodeJS.LTS --exact` (needs admin; globals in `%AppData%\npm` survive).
- **`better-sqlite3` is the only native dep**, pinned to v12+ for N-API prebuilds (one binary across Node versions, no per-machine recompile). After any Node *major* change, wipe `node_modules` and `npm install` so the ABI matches.

## Serving model — plain HTTP (do NOT re-add HTTPS)
- The dev/workshop UI is served over **plain HTTP** (Vite on :5173, proxying the Express backend). The self-signed HTTPS layer (`@vitejs/plugin-basic-ssl`) was tried and **reverted 2026-05-19**: self-signed certs can't be trusted across BYOD Safari + Chrome + mobile without installing a CA on every device, and Safari refused to extend a click-through to the websocket and to media downloads.
- **Don't reintroduce `@vitejs/plugin-basic-ssl` or `https: true`** in [client/vite.config.js](client/vite.config.js). The only feature it enabled — in-browser webcam capture (`getUserMedia`, needs a secure context) — was removed; image/video inputs are uploaded as files (a phone's file picker still offers "Take Photo").
- **Secure-context APIs don't work off-localhost over plain HTTP** — anything gated on `window.isSecureContext` (`navigator.clipboard`, `getUserMedia`, …) is unavailable on `http://<lan-ip>`. For clipboard, use [client/src/utils/clipboard.js](client/src/utils/clipboard.js) `copyToClipboard()` (tries the async API, falls back to a hidden-`<textarea>` + `execCommand('copy')`); never call `navigator.clipboard.writeText` directly.

Models: `seedvr2_ema_7b_sharp_fp16` (image) / `seedvr2_ema_3b_fp16` (video) + shared `ema_vae_fp16`. Backlog/superseded: Hunyuan3D 2.1. Full detail + the cross-cutting infra state (GS viewer = BUILT, multi-output UX = DONE/3D+N-image galleries, audio I/O = DONE/player+input; long-job robustness = READY) is in [implementation_plan.md](implementation_plan.md) under "Target workflows".

## Key implementation patterns

**Workflow registration:** Each workflow is a folder bundle: `workflows/<id>/<id>.api.json` (the ComfyUI API-format export) + `<id>.meta.json` (parameters, description, category). The `meta.json` is read-only; admins edit via UI (writes to `.config.meta.json` override file). This keeps the export distinct from deployment tweaks. **Optional `<id>_template.json`** (the original ComfyUI **UI/litegraph** export — subgraphs, groups, notes, layout) can sit alongside the api.json; it's detected by the registry (`entry.hasTemplate`/`templatePath`) and, when present, the admin editor's **Open in ComfyUI** hands *it* over (a fully editable graph) instead of the flat API graph — see the "Open in ComfyUI — template = editable graph" pattern below. It's **not parsed** (the parser only understands API format) and is purely for round-tripping the graph back into the ComfyUI editor.

**Open in ComfyUI — template = editable graph (auto-open):** The admin editor ([WorkflowMetaEditor.jsx](client/src/components/admin/WorkflowMetaEditor.jsx)) and the per-card button in the admin library ([WorkflowSelector.jsx](client/src/components/WorkflowSelector.jsx)) both boot ComfyUI (auto-launch the admin backend if down) and hand the current workflow over for editing, via the shared hook [useComfyOpener.js](client/src/hooks/useComfyOpener.js). **ComfyUI 1.45 has no URL param to open an arbitrary workflow**, and its startup tab-restore is **browser-localStorage per-clientId** (not server-writable), so we ship a **tiny opener extension** ([server/comfyui/opener/](server/comfyui/opener/), auto-installed into `<comfy root>/custom_nodes/comfyq_opener` by [openerExtension.js](server/comfyui/openerExtension.js)) that reads a custom **`?comfyq_open=<id>`** param and `loadGraphData`s the staged workflow onto the canvas. Flow: `openInComfy(id)` → `POST /admin/workflows/:id/open-in-comfyui` (stages `<id>_template.json` into `<comfy root>/user/default/workflows/<id>.json` **and** `adminCalibrator.ensureOpenerLoaded()`, which launches/one-time-restarts ComfyUI so the opener is loaded) → the tab opens `<comfyui>/?comfyq_open=<id>` and the graph loads itself. **Fallbacks:** `autoOpen:false` (external ComfyUI we can't restart) → open ComfyUI + tell the admin to pick it from the **Workflows sidebar** (the template is still staged); 409 (no template) → download the file to drag on the canvas (UI → editable graph; API → flat via `loadApiJson`). The older `stage-template` route is a harmless subset of the new one. `GET /admin/workflows/:id/edit-data` returns `templateWorkflow` (read fresh from `templatePath`) + `hasTemplate` next to `apiWorkflow`, and `hasTemplate` is on the `/workflows` summary too. **Template detection tolerates filename variance** — the registry falls back to any `*template.json` in the folder (not just `<id>_template.json`) as a defensive net; the bundles are all now on the canonical `<id>_template.json` name. The template is **display/round-trip only** — it never touches param detection (which needs API format) or job execution (the api.json still runs). Staging overwrites `<id>.json` each click (our bundle template is the source of truth; edit in ComfyUI → re-export back into the bundle to persist). *(The sibling per-card **"Activate & serve"** button — `activate(id)` → student mode — lives in the same card row; see the 2026-07-01 progress entry.)*

**Output detection (generic):** No `class_type` whitelist. [server/media/mediaTypes.js](server/media/mediaTypes.js) classifies by file extension: `.glb/.gltf` → model3d, `.spz/.splat/.ksplat` → splat, `.mp3/.wav/…` → audio, `.mp4/.webm/…` → video, else image. New output formats Just Work™ — no code changes needed.

**Subfolder serving:** ComfyUI save nodes write to subfolders (e.g., `SaveAudioMP3` → `audio/track.mp3`). The wire carries the full output-root-relative filename; [server/executor/jobExecutor.js](server/executor/jobExecutor.js) folds the subfolder into `filename` and clears the `subfolder` field so `/images/:filename(*)` serves them without breaking existing routes.

**Multi-output galleries:** When a job produces >1 image, the lightbox renders [ImageGallery.jsx](client/src/components/ui/ImageGallery.jsx) (main image + thumbnails + prev/next). When it has both a splat and a mesh, a toggle switches between the 3D viewers. Audio outputs render the AudioPlayer. The Scheduler grid shows a "{N} views" badge for multi-output jobs.

**Student param form is ONE shared component (`DynamicParamFields`):** [client/src/components/DynamicParamFields.jsx](client/src/components/DynamicParamFields.jsx) renders the exposed-parameter form from a `parameter_map` and is the single source of truth for how students see inputs. It's rendered by **both** [BookingDialog.jsx](client/src/components/BookingDialog.jsx) (the real booking, with live state) **and** the admin [WorkflowMetaEditor.jsx](client/src/components/admin/WorkflowMetaEditor.jsx) "Student preview" (throwaway state) — so the admin's preview can never drift from production. Props: `paramMap`, `values`, `onValueChange(key,value)`, `mediaPreviews`, `recalledMedia`, `mediaChangeHandler(key)→(file)→void`, `mediaRemoveHandler(key)→()→void`. The editor preview converts the editor's param-array (`nodeId`, `enabled`, …) into the wire `parameter_map` shape (key→{type,label,default,options,min,max,step,disabledWhen,required,field,order,enabled}); `field` is needed because seed detection (`isSeedParam`) keys off it. **If you add a new param *type*, add its branch here once** and both the booking form and the preview get it. **Prompt boxes (textarea params, 2026-09-15)** open at 208 px (104 px when the key/label says "negative"), are vertically resizable (72 px – 70vh), and remember the height a student drags to in `localStorage` (`comfyq.promptBoxHeight.prompt|negative`, per browser); the booking dialog is `max-w-2xl` so long prompts get width too. Keep `transition-colors`, not `transition-all`, on a resizable textarea — a height transition makes the drag lag.

**Param field gating (`disabledWhen`):** A parameter can declare `disabledWhen: { param, equals }` in the meta to grey itself out when another param holds a value. Used for either/or prompts (raw vs. LLM-enhanced). The field still submits; the workflow's switch node ignores the unused branch. **Preserved through the editor (2026-06-26):** `edit-data` returns it and the editor's save payload re-sends it, so an admin open+save no longer drops a workflow's gating (there's still no UI to *edit* `disabledWhen` — it round-trips untouched).

**Mask-draw input (`mask` param type):** For inpainting, a param `type: "mask"` renders [MaskDrawField.jsx](client/src/components/capture/MaskDrawField.jsx) instead of an uploader: the user picks a base image and **brushes the region to replace** in a **near-fullscreen paint modal** (`createPortal` to `document.body` so it escapes the booking dialog's transform/stacking context — the canvas fills the viewport for precise masking; the form shows a small composited preview + a "Paint/Edit mask" button), and the component composites it into a single RGBA PNG where the painted area is **transparent** (`globalCompositeOperation='destination-out'`). ComfyUI's `LoadImage` derives `MASK = 1 − alpha`, so transparent → mask 1.0 → "inpaint here" — one file feeds both the image (out 0, RGB) and the mask (out 1). The produced File flows the **same** path as an image upload (`onChange`→`handleMediaChange`→`/upload`→generic materializer), so the server is untouched. `mask` is treated as `image` everywhere the value flows: it's in `MEDIA_TYPES` (BookingDialog), required-by-default + `inferType` (parser), `maxInputEdge` (meta editor), and calibration stages a plain image for it (no alpha → empty mask → no-op inpaint, still runs the sampler → valid timing). Brush colour is cosmetic only (export reads alpha; recolour is `source-in`). Adding the type means editing both the zod enum ([schemas.js](server/config/schemas.js)) **and** the duplicated `PARAM_TYPES` array in WorkflowMetaEditor — they aren't shared. **Mask polarity** is the standard ComfyUI convention (white = inpaint, the graph's `mask_invert:false` confirms); flip in `MaskDrawField.commit()` if a rig run inpaints the inverse.

**Dynamic dropdown params (`lora` type):** A param `type: "lora"` renders a `select` whose options are populated **server-side at booking time**, not baked into the meta. [modelOptions.js](server/workflows/modelOptions.js) `listModelFiles(comfyRoot, subdir, prefix)` scans `<comfy root>/models/<optionsDir|'loras'>` on the ComfyQ host's disk (not via ComfyUI's API — works whether ComfyUI is up or not), keeps weight files whose name starts with the `optionsFilter` prefix (e.g. `krea2_` → only Krea-compatible LoRAs), sorts, and TTL-caches (8 s — the realtime bus rebuilds the parameter_map on every broadcast). [realtimeBus.js](server/realtime/realtimeBus.js) `_buildParameterMap(exposed, comfyRoot)` sets `options` + prettified `optionLabels` (extension stripped) for `lora` params, always keeping the `default` selectable so the field never renders empty (off-rig or missing dir → just the default). The wire value is the plain `.safetensors` filename, so the **generic materializer / recall / calibration treat it like any string** — only the widget differs (shared `select` branch in [DynamicParamFields.jsx](client/src/components/DynamicParamFields.jsx), which reads `optionLabels`). `optionsDir`/`optionsFilter` live in meta.json and **round-trip through the editor** (save payload + edit-data merge, like `disabledWhen`); the base meta owns the `type` (config-overrides only patch label/default/order/enabled). The admin "Student preview" fetches the same list from `GET /admin/loras?dir=&filter=`. To offer a different model family/dir, set `optionsFilter`/`optionsDir` in the meta — **no code change**. Adding the type touched the zod enum ([schemas.js](server/config/schemas.js)) **and** the duplicated `PARAM_TYPES` array in WorkflowMetaEditor (not shared). First used by [image_krea2_turbo_t2i_lora](workflows/image_krea2_turbo_t2i_lora/).

**Text outputs (LLM / caption):** Nodes that emit text instead of a file (`PreviewAny` "Preview as Text", `ShowText`, …) report a `text`/`string` array in `history[promptId].outputs`. `_collectText` in [server/executor/outputCollector.js](server/executor/outputCollector.js) collects these as a `kind:'text'` output with the string **inline on the wire** (no file to serve); [server/executor/jobExecutor.js](server/executor/jobExecutor.js) forwards `o.text`, and `ImageLightbox`/`MediaPreview` render the caption. No `class_type` coupling — any text-emitting node Just Works, so image/video→text workflows (Gemma describe-it) land zero-code. First exercised by the Gemma 4 captioners.

**Friendly failure messages (`humanizeFailure`):** ComfyUI execution errors reach the user as the job's failure `reason`, computed at two sites — the WS `execution_error` event ([localComfyUIWorker.js](server/workers/localComfyUIWorker.js)) and the history-status fallback ([jobExecutor.js](server/executor/jobExecutor.js)); both carry the failing node's `class_type`. `humanizeFailure(message, nodeType)` in [errorMessages.js](server/executor/errorMessages.js) rewrites known signatures into actionable text (first case: no-face on a face-cropper node → "upload a clear photo with a single, fully visible face"), and **falls through to the raw message** for everything else (errors are clarified, never swallowed). Add new mappings here, not at the call sites. Keep guards tight (e.g. an OOM on a face node is *not* a no-face problem) to avoid mislabeling.

**Experimental bundles:** a newly promoted workflow ships `"experimental": true` in its meta.json; the admin library badges it and the **Validate** button clears it (`PUT /admin/workflows/:id/experimental`, writes meta.json itself so the sign-off is committed). Purely a label — experimental bundles calibrate and serve normally. **Promotion recipe for future candidates:** convert with [tools/ui-to-api/convert.mjs](tools/ui-to-api/convert.mjs) (ComfyUI's own `graphToPrompt`, never by hand), keep only final-result outputs, rewire in-path preview passthroughs, validate params against `/object_info`, calibrate, **then check the output content** (a black image still reports success).

**Perf-flag opt-out (`requirements.disabledPerfFlags`):** the rig-wide `use_sage_attention` / `fp16_accumulation` speed-ups can make a model save black images without any error (Qwen-Image-Edit + Sage; SeedVR2 7B int8 + fp16 accumulation). A bundle lists the flags it can't run with; [perfFlags.js](server/workers/perfFlags.js) masks them for the ComfyUI that serves (student boot, which also replaces a running ComfyUI that has them) or calibrates (AdminCalibrator) that workflow. Diagnose a black output by toggling one flag at a time before blaming the graph.

**Optional image inputs (`required: false` on an image/mask param, 2026-09-14):** until now every media param was mandatory — the booking form ignored `required` and **returned silently** when an upload was missing (the owner's "Start does nothing" on `utility_ltx2_5_video_deblur_upscale`, whose optional start image was still `required: true`). Now: the form asks only for media where `isMediaNeeded()` ([DynamicParamFields.jsx](client/src/components/DynamicParamFields.jsx)) says so — mandatory unless `required: false`; an optional upload gated by `disabledWhen` is needed only while its toggle switches it on — and names what is missing instead of doing nothing; a gated upload field greys out. **Server side** ([optionalMedia.js](server/workers/optionalMedia.js), called in `worker.submit`): ComfyUI validates **every** `LoadImage` in the prompt, even one only a switched-off branch reads, so an optional image left empty is filled with a fixed 64×64 black **`comfyq_placeholder.png`** (written once by `InputUploader.ensurePlaceholderImage()`, outside the swept `comfyq__` prefix); an upload switched ON but missing fails at submit with a clear message. **★ The graph must guarantee the placeholder is never used** — check that every consumer of the LoadImage is behind a switch or a `bypass` driven by the same toggle before marking it optional (on LTX 2.5 the image also feeds `LTXVImgToVideoInplace`, whose `bypass` = NOT toggle returns the latent untouched). Image/mask only — there is no neutral placeholder video/audio. Applied to the deblur and `video_edit_ltx2_5_iclora_union_control` start images (toggle moved above the image field). Verified end to end on the rig: a socket-booked deblur job with no start image at 1088 px completed (1088² video with the original audio); the switched-on case fails at submit. Tests: `node server/workers/optionalMedia.test.js` (in `test:storyboard`).

**Prompt guides (`promptGuides`, 2026-09-14):** a meta can list official prompting guides — `promptGuides: [{ label, url, tip? }]` (zod: url must be a URL) — and ComfyQ shows them **up front**: in the student Timeline's active-workflow card and at the top of the booking dialog (the first guide's `tip` is a one-line style summary printed under the links), plus compact links on admin library cards ([PromptGuideLinks.jsx](client/src/components/PromptGuideLinks.jsx); data rides `summary.promptGuides` → `workflow_info.promptGuides`). Editable in the metadata editor ("Prompt guides" rows; rows without a URL are dropped on save). **27 bundles carry them** (every bundle that prompts FLUX.2, Krea 2, Ideogram 4, MiniMax H3 or LTX; the Krea character sheet and TripoSplat load those models but expose no prompt, so they have none). URLs were **each fetched and verified 2026-09-14**: FLUX.2 → docs.bfl.ai `prompting_guide_flux2` (+ `prompting_editing_single_reference` / `…multi_reference` for edit bundles; Klein does not expand short prompts); Krea 2 → `github.com/krea-ai/krea-2/blob/main/docs/prompting.md` (+ Krea blog “start vague”); Ideogram 4 → docs.ideogram.ai “4. JSON Prompting (Ideogram 4.0)” (+ `ideogram-oss/ideogram4` repo doc) — the bundle's default JSON uses the same three top-level keys; MiniMax H3 → the `MiniMaxAI/MiniMax-H3` HF docs `VIDEO_PROMPT_WRITING_GUIDE_base_en.md` (t2v/i2v) or `…_ref_en.md` (the four reference/control bundles) + Comfy-Org's H3 prompt page; LTX → `docs.ltx.io/open-source-model/usage-guides/prompting-guide` (docs.ltx.video now 403s) + ltx.io blog LTX-2.5 / LTX-2.3 guides, the union-control page for the IC-LoRA trio (“describe the look, not the motion”) and the IC-LoRA page for deblur/3DReal. ★ The deblur bundle's `ltx-2.5-22b-ic-lora-pixel-spatial-upscaler-x2` is Lightricks' **Pixel Spatial Upscaler** adapter (no trigger phrase), **not** the DEBLUR-trigger deblur LoRA — the candidate's download link pointed at the wrong HF repo (`LTX-2.3-22b-IC-LoRA-Deblur`, which only holds `ltx-2.3-22b-ic-lora-deblur-0.9`); the right repo is `Lightricks/LTX-2.3-22b-IC-LoRA-Pixel-Spatial-Upscaler`.

**Collector skips inputs and de-dupes paths:** [outputCollector.js](server/executor/outputCollector.js) ignores `type:'input'` records (LoadVideo previews its upload) and doesn't re-collect a file pass 1 already found via an absolute `fullpath` (VHS_VideoCombine).

**Calibration (auto, single run split into load+gen, admin-mode):** [server/benchmark/benchmarkService.js](server/benchmark/benchmarkService.js) runs the workflow **once** (explicit `/free` first so models load) and splits the run at the first sampler `progress` event: start→first-step = `modelLoadSec`, first-step→end = `estimatedDurationSec`/`warmDurationSec` (the recurring/optimal cost the timeline uses); full wall time = `coldDurationSec` (first-run incl. load); plus `samplesPerSec` + `gpu`. **Do NOT add a second "warm" run** — ComfyUI caches identical graphs and returns the cached result in ~1s, which made calibration report 1s for a 25s job (regression fixed 2026-06-13). Instead `_randomizeSeeds()` bumps every literal `*seed` node field **and** `_buildCalibrationParams` randomizes every exposed seed param, so the single run always actually executes (cache-immune, even on re-calibration). Inputs **auto-resolved from `config.assets.dir`** (`D:\_assets`): `_resolveAsset(type)` picks a median image / smallest video / audio clip, staged via the worker's `InputUploader` (image falls back to a built-in PNG; missing video/audio asset → clear error). When content matters (a person to track, a face, a sound track), set the media param's `warmupParams` value to **`asset:<file name in the assets dir>`** to stage that exact file (2026-09-14). **The load/generation split assumes the first progress event is the first sampler step** — a node whose progress bar counts tiles or frames (PiD's `LatentTiledPiDDecode`) bills its first unit as model load and under-reports the warm time; measure those by hand (see `utility_pid_image_upscale`). Gauge button works in **admin mode** via [server/benchmark/adminCalibrator.js](server/benchmark/adminCalibrator.js) (lazily spawns/attaches ComfyUI, reuses it, idle-frees VRAM, leaves ComfyUI running on shutdown). **No UI, no uploads.** Student-mode caveat: calibrate while the queue is idle (executor + calibration share the one worker). **Config freshness (2026-06-21):** `AdminCalibrator` reads ComfyUI paths **fresh from `configManager` on each launch/calibrate** (getters, not a boot-time snapshot), so a path saved in Settings is honored immediately by the gauge and the *Launch ComfyUI on the network* button; it restarts a ComfyUI it spawned when the saved paths change (don't reintroduce a constructor snapshot — that was the "launch ignores my new path" bug).

**Image upload guard:** Three-layer protection against OOM crashes from oversized images: (1) client throws `ImageProcessError` on HEIC/decode failure; (2) [MediaCaptureField.jsx](client/src/components/capture/MediaCaptureField.jsx) shows inline error; (3) [server/routes/uploads.js](server/routes/uploads.js) backstop rejects HEIC (extension + ftyp magic byte) and images not fitting 1920×1080 box in either orientation. Server uses `image-size` library (pure JS, no native dep).

**Light-theme color tokens:** Theme is class-based (`.dark`/`.light` on `<html>`) over CSS-var tokens in [client/src/index.css](client/src/index.css) (`@theme` → `--color-*`). A compat hack maps **`--color-white → --text`** so the ~150 existing `text-white` usages stay readable in light mode without a sweep. The gotcha: that makes `text-white`/`bg-white` on a **solid accent fill** (`bg-primary`, `bg-danger`, …) dark-on-dark in light mode. For text/icons/knobs on an accent fill use the **`--color-on-primary`** token (`text-on-primary`/`bg-on-primary`) — it stays light in both modes. New surfaces should prefer `bg-background`/`bg-surface` + `text-foreground`/`text-muted`, not hardcoded slate/black/white.

**Input retention & asset reuse:** Booked-job media uploads go to `<comfy>/input/comfyq_session__*` and the filename is stored in `job.paramValues` (so it's on the wire). The periodic `sweepStale()` ([inputUploader.js](server/workers/inputUploader.js)) only deletes the **`comfyq__`** (job-scoped, execution-time) prefix — **not** `comfyq_session__`, so the original uploads persist. "Use these settings" exploits this: [BookingDialog.jsx](client/src/components/BookingDialog.jsx) re-binds the recalled filename directly (no re-upload; the materializer injects it) and previews/plays it via `GET /input-media/:filename` ([uploads.js](server/routes/uploads.js), restricted to the `comfyq_` prefix + pinned inside the input dir).

**ASAP booking:** A booking with no slot picked sends `scheduledTime: null`; the server treats null-or-past as ASAP and schedules into the earliest non-colliding slot via `jobQueue.nextFreeSlot(now, durationMs)` (greedy walk over active jobs) instead of throwing a collision. An explicit future time keeps the normal `findCollisions` guard. `findReady` orders by `scheduled_at ASC, created_at ASC` (FIFO tiebreaker). The BookingDialog's segmented **ASAP / Pick-a-time** toggle drives `scheduledTime` (null vs a timestamp).

**Prompt display resilience:** `pickHeadlinePrompt()` in [BookingDialog.jsx](client/src/components/BookingDialog.jsx) finds the user's text at submit time (prefers textarea params, skips negative-keyed ones). `getDisplayPrompt()` in [jobDisplay.js](client/src/utils/jobDisplay.js) mines `job.params` at render time so historical jobs display even if exposed under non-`prompt` keys (e.g., LTX `positive_prompt`, Ideogram `description`).

## Federation (Phase F — F1+F2 shipped via beacon + packaged auto-updating desktop app, in user testing 2026-06-28; F3–F6 deferred)
The final v2 phase is multi-instance LAN federation. **The first slice shipped (2026-06-27→28)** as a **UDP multicast status beacon** + a standalone **Electron fleet monitor** (`desktop/`) — now packaged as a self-updating installer (see the "Desktop app — installers + GitHub auto-update" Latest-progress entry) — a deliberate divergence from the originally-locked mDNS/in-browser-panel design — see the Latest-progress entry above and [implementation_plan.md](implementation_plan.md) → "Phase F". Server code lives under [server/federation/](server/federation/); the beacon and `GET /federation/self` share one `buildSnapshot()`. **Conventions to keep:** beacon transport is built-in `dgram` UDP multicast (no mDNS dep added); federation is **on by default** but fully gated by `config.federation.enabled` so a disabled boot is byte-for-byte today's single-instance behavior; the new `config.instance`/`config.federation` schema blocks are **optional/defaulted** so existing `config.json` validates unchanged. The remaining locked design (mDNS, cluster-secret auth, cross-instance admin actions, AdminConfig panel, student station picker, orchestrator role) stays deferred. **Implication for other work:** don't bake in single-instance assumptions — if a feature surfaces state that should be aggregable across peers, expose it where `buildSnapshot()` / a future `/federation/*` route can return it without a schema migration.

## Conventions
- **API-format workflows only** (no Litegraph auto-conversion). **Generic output detection** by file extension, not `class_type`.
- Commit/push only when the user explicitly asks.
